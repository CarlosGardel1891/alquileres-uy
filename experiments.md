# Experiments — alquileres-uy

## Fixture contract runs

**These numbers come from synthetic fixture data and are not project or
market results.** They exist so we can prove the pipeline runs
end-to-end and produces stable artifacts. Every fixture value is
computed under the strict `tune-then-refit-v2` protocol: validation
metrics from tuning models fit on train only; test metrics from final
models refit on `train + validation`.

Fixture: `tests/fixtures/models/etl_run` — 240 rows, 183 unique dates,
generated by `scripts/_generate_model_fixture.py` with seed `20260805`.

Row counts: train `169`, validation `35`, test `36`. Split cutoffs:
train → validation `2025-07-30`, validation → test `2025-09-13`.

**Fixture selection result:**

* `best_overall_model = linear` (smallest validation MAE — tuning-only)
* `serving_candidate = baseline` — inside the practical-tie set
  `{baseline, linear}` (anchor 52.66, threshold 57.66); baseline wins
  by simplicity.
* `residual_interval` (validation, tuning model of baseline):
  `q10 = −83.53`, `q90 = 108.05`, `coverage_on_validation = 77.1%`.
* `deployable = false`, `blocked_reason = "fixture training run"`.

**Why the LightGBM validation MAE changed (80.23 vs. the earlier 38.78).**
The previous number came from a leaky protocol that refit LightGBM on
`train + validation` *before* computing validation metrics. The
`tune-then-refit-v2` protocol removes that leak: validation MAE is now
measured on the tuning model, which never saw validation. The new
number is the honest one.
